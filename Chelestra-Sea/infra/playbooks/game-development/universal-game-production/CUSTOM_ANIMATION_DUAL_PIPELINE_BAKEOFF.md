# Universal Custom Animation Dual-Pipeline Bakeoff

## Purpose

For custom motions not acceptably covered by a provider preset, compare two independently produced animation candidates under identical conditions and collect evidence over time.

Default reusable lanes:

1. Houdini KineFX
2. Blender

A project overlay may name different DCC/motion lanes, but the fair-input, blinded-review and data-collection contract remains the same.

## When required

- bespoke class/weapon/ability animation;
- constrained interaction;
- boss/monster signature motion;
- special death;
- acting/performance motion;
- substantial provider-preset derivation;
- owner-designated A/B test.

A direct provider preset that passes all technical, runtime and creative gates does not require duplicate production.

## Common-input contract

Both candidates use the same:

- source model/rig/skin;
- source preset/mocap/video/pose brief;
- duration/FPS;
- root-motion policy;
- IK/prop/weapon/environment constraints;
- contact/VFX/SFX/gameplay markers;
- target cameras and test scene;
- export/compression/runtime contract;
- time and manual-touch budget.

First-pass producers do not copy each other's keyframes or scoring notes.

## Candidate package

Each lane supplies:

- editable source;
- deterministic script where practical;
- baked runtime skeleton/action;
- review and optimized exports;
- action metadata/markers;
- normal-speed and slow-motion evidence;
- gameplay and close-up views;
- technical validation report;
- runtime/device capture;
- production time, retries, interventions, failures, file size and performance;
- provenance and rollback.

## Automated admissibility

Check:

- skeleton/bone map;
- finite transforms;
- duration/FPS;
- root motion;
- foot/hand/prop/constraint tolerance;
- joint limits and deformation;
- collision/clipping;
- loop/start-end delta;
- contact markers;
- transition entry/exit;
- runtime import/playback;
- target-device performance/errors.

A candidate that still fails a critical gate after bounded repair cannot win.

## Blind review

A coordinator labels candidates A/B without revealing pipelines.

An independent AI reviewer scores:

- intent/silhouette;
- gameplay readability;
- natural mechanics;
- constraint/contact integrity;
- deformation;
- timing and recovery;
- loop/transitions;
- project style fit;
- runtime efficiency;
- automation reliability.

The owner receives synchronized blinded comparisons and chooses:

- A wins;
- B wins;
- tie/keep both;
- category split;
- rework both;
- reject/use another route.

Reveal pipeline identities only after the verdict is stored.

## Data and routing decisions

Store every result in a project experiment registry.

Review aggregate results at 10, 25, 50, 100, then each additional 50 completed bakeoffs.

No pipeline retires automatically. Global or category-specific routing changes require representative samples, quality/time/failure evidence, and explicit owner approval.

The likely long-term result may be category routing rather than one global winner.
